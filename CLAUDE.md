# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A self-hosted, offline-first English vocabulary trainer (背单词). Static site, no backend, deployed as a PWA to GitHub Pages. Bilingual UI (zh/en). Word data is built offline from ECDICT + Tatoeba and shipped as static JSON.

## Commands

```bash
npm install
npm run dev          # vite dev server (port 5173, auto-open)
npm run build        # tsc --noEmit (type-check) + vite build -> dist/
npm run typecheck    # tsc --noEmit only
npm run preview      # serve the build — PWA/service worker only works here, NOT in dev
```

Data rebuild (only needed when regenerating word lists/sentences; outputs land in `public/data/`):
```bash
npm run build:data        # ECDICT csv -> per-list JSON + meta.json. Needs scripts/sources/ecdict.csv (or ECDICT=...)
npm run build:sentences   # Tatoeba -> sentences.json. Needs scripts/sources/{sentences,links}.csv
```

There is **no test framework** in this project — do not invent test commands.

## Architecture

**No UI framework.** The DOM is built imperatively with a hyperscript helper `h(tag, attrs, ...children)` (`src/ui.ts`). `attrs` special-cases `class`, `html` (innerHTML), `style`, and `on*` event handlers; everything else becomes a `setAttribute`. In `attrs`, `null`/`undefined`/`false` are skipped (a `false` value omits the attribute entirely rather than emitting `disabled="false"`); in `children`, `null`/`undefined`/`false`/`true` are dropped — so conditional rendering (`cond && h('span')`) and boolean-style attributes (`{ disabled: isDone }`) are safe no-ops, never literal strings. When adding UI, use `h()` and append to a container element — match the surrounding views. `shuffle()` (Fisher–Yates) and `toast()` (a transient bottom banner) also live in `ui.ts`. `src/dropdown.ts` exports `dropdown({ label, options, current, onChange })` — a fully-styled custom listbox (closed + open states, outside-click-to-close, ARIA roles) that replaces native `<select>`; the settings page uses it for every option picker, so reach for it rather than `<select>` when you need a styled chooser.

**Hash-based router** (`src/main.ts`): an array of `{ re, view }` entries maps `location.hash` to a view function. Each **view is a function** `(params, ctx) => ViewResult` where `ViewResult = { el, cleanup? }`. The router calls the previous view's `cleanup()` before swapping, so any event listeners a view attaches to `document`/`window` must be removed in `cleanup()` (see `study.ts` keyboard handling), and the same goes for non-DOM subscriptions (`settings.ts` detaches its `onKokoroStatus` listener in `cleanup` so it can't touch dead DOM). Navigation is `ctx.navigate('#/route')`. `index.html` ships an inline startup splash (`#boot`, spinner + wordmark pulse) that `main.ts` hides once `meta.json` is preloaded; keep it self-contained and use explicit `top/right/bottom/left` offsets (the `inset` shorthand breaks on old WebViews). `#/list/:id` is the per-list word browser (status badges, filter chips, multi-select, bulk mark/unmark known); `#/list/new` creates a custom list — it must be registered **before** the `:id` route since `new` matches `[\w-]+`. Custom lists are created via `createUserList()` and auto-filled from built-in data via `getWordIndex()` (`data.ts`); `deleteUserList()` removes a list, wipes its SRS state in one pass, and clears `selectedList` if it pointed there (so the boot prefetch doesn't 404 forever).

**State is localStorage-backed**, single source in `src/store.ts`. Five keys:
- `recite:state` — per-word SRS state, keyed **`${listId}:${word}`** (isolated per list). `WordState.known` marks a word "already known": `buildSession` skips it, `statsByList` counts it as learned (not due), `getDifficult` excludes it. Set/cleared in bulk via `markKnown()`/`unmarkKnown()`.
- `recite:meta` — global settings (selected list, voice, dailyLimit, spellCountdown, theme, lang, ttsEngine, retention). Defaults live in `defaultMeta` in this file; to **add a setting** also extend the `Meta` interface in `src/types.ts`, wire a control in the settings UI, and add any label strings to both i18n dicts. `selectedList` is written by the three per-list modes on entry and read only by `main.ts`, which prefetches that list's JSON after boot so resuming is instant.
- `recite:activity` — `{ 'YYYY-MM-DD': count }` for the streak + heatmap
- `recite:daily` — `{ d: 'YYYY-MM-DD', n: { [listId]: count } }`: new words introduced **today**, per list. Drives the 每日新词 quota across sessions; the date rolls over lazily on read (`getDaily()` never writes). `bumpNew()`/`todayNew()` are the accessors (study's undo passes `-1`).
- `recite:userlists` — user-created custom word lists (`UserList[]`; ids are `user-<base36>`, colon-free so they're safe as `listId`). `loadMeta()`/`loadList()` in `data.ts` merge + serve them transparently, so study/spell/dictation/stats/home work unchanged. `clearAll()` keeps the list definitions (only their SRS state is wiped).

`getState()`/`getWordState()` are backed by an in-memory cache (parsed once per tab), so the hot path (`schedule()` + `bumpActivity()` on every grade) no longer re-parses the whole SRS object each time. The cache is dropped on cross-tab writes (a `storage` listener) and on `importData()`/`clearAll()`. `statsByList()` rolls up per-list started/due counts in one pass (used by home + stats). A write that hits `QuotaExceededError` is logged and surfaced via the `onQuotaExceeded()` hook (wired in `main.ts` to a toast) rather than failing silently. Backup/restore lives here too: `exportData()`/`importData()` serialize all five keys; `clearAll()` wipes SRS state + daily-new counters + activity but **keeps** settings (meta). `getDifficult()` scans all of `recite:state` for words flagged `diff` — it's how the cross-list drill view finds its queue.

**FSRS spaced repetition** (`src/srs.ts`, via `ts-fsrs` — the scheduler MaiMemo open-sourced, now Anki's default): `schedule(listId, word, q)` maps the grade buttons' q values (1/3/4/5) onto FSRS ratings (Again/Hard/Good/Easy), advances the card's stability/difficulty, and persists a `WordState` extended with `s`/`d`/`l`/`state`. Short-term learning steps are disabled (`enable_short_term: false`, empty step ladders): the 墨墨-style in-session requeue already covers same-session reinforcement, and the whole app assumes day-granularity due dates. `request_retention` comes from the retention setting; schedulers are cached per retention value. **Legacy SM-2 states migrate lazily** on the next grade — the old `interval` becomes the stability, `ef` maps inversely to difficulty (`11 - 2.5·ef`, clamped 1..10) — so existing progress carries over. Early/late reviews are compensated intrinsically (a word remembered well past its due date gets a bigger interval jump). `st.diff` flags difficult words (set on Again, cleared on Good/Easy, kept on Hard).

**Session building** (`src/session.ts`): SRS-due reviews first, then the next unseen words ("personal progression" — continues where you left off). Both buckets are shuffled. 墨墨-style quota: `dailyLimit` caps **new words only**, per list, **across the whole day** (counted in `recite:daily`, so re-entering a mode doesn't grant another batch) — due reviews are uncapped and never consume the quota, so a backlog day still learns its full share of new words (the home badge shares the policy via `newToday()`, and `dailyLimit()` centralizes the `|| 50` default). A word's first-ever grade (`getWordState() === null` before `schedule()`) is what counts as "new" — in study, spell, and dictation alike.

**Data loading** (`src/data.ts`): word lists / meta / sentences are lazy-`fetch`ed from `public/data/*.json` with an in-memory `Map` cache that stores the in-flight **promise** — concurrent callers (e.g. a view entered while the boot prefetch is running) join the same request instead of duplicate-downloading, and a rejected promise is dropped from the cache so it retries. URLs are built from `import.meta.env.BASE_URL` (so subpath deploys work — `base: './'` in `vite.config.ts`). **Sentences are optional**: `loadSentences()` returns `{}` on failure and callers degrade gracefully. Never assume sentences exist.

**Data freshness / caching** — two caches sit in front of the JSON, and both bite when you rebuild `public/data/`: (1) the Workbox service worker serves `/data/*.json` `StaleWhileRevalidate` (`vite.config.ts`, cache name `recite-data`), so deployed users see the *previous* version first and the new one only on the next load; (2) `src/data.ts` holds its `Map` cache for the whole page lifetime, so an already-open tab won't pick up changes until reload. A second runtime cache (`recite-kokoro`, `CacheFirst`, 90-day expiry) stores the kokoro engine chunk once the user enables offline TTS — it's deliberately excluded from precache (`globIgnores`) to dodge the 2 MiB Workbox limit and keep the default install lean. The "Download offline" button (`cacheAllData()` in `src/pwa.ts`) is a manual prefetch that warms the `recite-data` SW cache by fetching every data file once. The service worker is only registered in `preview`/production, never in `npm run dev`.

**i18n** (`src/i18n.ts`): homegrown `t(key, vars)` with zh/en dictionaries and `{var}` interpolation. `setLang()` persists and **reloads the page** (no reactive re-render). Theme is the exception: `src/theme.ts` toggles a `.dark` class on `<html>` **live** (no reload) and re-applies automatically when the OS scheme changes while in `auto` mode. Word *content* is never translated; localized list names/descriptions come from `listName()`/`listDesc()`. New UI strings must be added to **both** the `zh` and `en` dicts (`t()` falls back to the `en` dict, then to the raw key, so a missing key renders as the key string).

**Views & learning modes** (`src/views/`; one file per route plus shared modules). `views/common.ts` holds the repeated pieces — `topbar()`/`setProgress()`/`loadFailEl()`/`loadingEl()` and the study/drill card sections (`entryHead`, `meaningBlock`, `gradesRow`) — and `views/quiz.ts` is the entire spell/dictation flow (countdown timer, binary grading: wrong/timeout → `q=1`, correct → `q=4`; feedback reveal; done screen; wrong answers requeue once at the queue tail, 墨墨-style), with `spell.ts`/`dictation.ts` reduced to thin hook configs (`prompt`, `onPrompt`, `feedbackExtra`, `repromptOnSentences`; hooks must keep `t()` lazy — they're built at module scope, before `initI18n()` runs). The **per-list** modes (`study`, `spell`, `dictation` — all take a `listId` param) share the same `buildSession()` + `schedule()` loop: `study` is flip-card reveal → grade via the shared `GRADES` constant (`src/grades.ts`, q 1/3/4/5 with labels/classes, used by `study` and `drill`); `spell` clozes an example sentence and asks you to type the word; `dictation` plays the word via `speak()` and asks you to type it with the meaning hidden. **The first card renders as soon as the list JSON arrives** — `loadSentences()` (4+ MB) streams in behind it and re-renders to attach examples (quiz re-renders only while the current card is in the input-free feedback state, so a slow sentence load never wipes typing), and `main.ts` prefetches `sentences.json` + the last `selectedList` after boot for returning users only (a browse-only first visit doesn't pull 4+ MB). `study` also requeues weak grades (q<4 — forgot/hard) for one more pass at the end of the same session, 墨墨-style, capped at once per word; the done-screen totals count **unique** words graded, mastered = final grade q>=3. The **global** views ignore `listId` and read across *all* SRS state: `drill` pulls every `st.diff` word from every list (`getDifficult()`), `search` builds an in-memory index over all lists — custom-list edits must call `invalidateSearchIndex()` (`src/views/search.ts`) or the index goes stale (the list view does this after bulk edits); `stats` drives the streak/heatmap from `recite:activity`. Pronunciation is the single path `speak(text, lang)` in `src/speech.ts`: it uses the Web Speech API when the browser has a usable engine (engine errors still fall back; `canceled`/`interrupted` events — a newer `speak()` took over via `synth.cancel()` — do **not**, or the two engines would double-speak), and otherwise falls back to **kokoro-js** (Kokoro-82M neural TTS, runs locally via WASM) **automatically** — the 设置 → 发音引擎 (`ttsEngine`) setting only picks system-first vs always-offline. First use downloads an ~80–100 MB model from Hugging Face (cached by the service worker thereafter); the download state surfaces via `onKokoroStatus()` (a global toast in `main.ts` plus the settings status line — it supports multiple listeners). It's still a best-effort no-op when the download fails, so never assume audio plays. `kokoro-js` is aliased to its self-contained `dist/kokoro.web.js` in `vite.config.ts` (the package's npm entry imports Node-only `fs`/`path`) and excluded from dep pre-bundling; it is dynamically `import()`-ed from the fallback path only, so it never lands in the main bundle. Only `study` and `drill` attach a `keydown` listener on `document` — **always remove it in the returned `cleanup()`** or the key binding leaks into the next view (`spell`/`dictation` listen on their own `<input>`, which is destroyed with the view DOM; their `cleanup` clears the countdown timer). Bindings differ per view (study: Space = reveal, 1–4 = grade, z = undo). `study` keeps a one-step undo: `grade()` snapshots the pre-grade `WordState` into `undoLast`, so a later `undo()` (button or `z`) restores it via `setWordState()`/`removeWordState()`, rolls back the `bumpActivity()` and session counters, and drops a still-pending requeue — only the immediately previous card is revertible.

## Data pipeline

`public/data/*.json` are committed build artifacts served as static assets. `meta.json` is the source of truth the app reads for the list catalog (`id`, `name`, `desc`, `file`, `count`).

- `scripts/build-wordlists.js`: streams `ecdict.csv`, buckets rows by ECDICT `tag` into lists, **frequency-sorts** (most common first), de-dupes, slimms to `{word, phonetic, pos, translation, definition}`, and writes one JSON per list plus `meta.json`. AWL is special: headwords come from `scripts/data/awl.txt`, backfilled with phonetic/meaning from ECDICT (it has no tag).
- The `LISTS` and `META.lists` arrays in that script **must stay in sync** — they define which lists exist.

### Adding a new word list
1. Add entries to both `LISTS` (with ECDICT tag) and `META.lists` in `scripts/build-wordlists.js`.
2. Add the list id to the `LIST_NAMES` and `LIST_DESC` maps in `src/i18n.ts`.
3. Add a `data/*.json` file (built) and ensure `public/data/meta.json` reflects it.
4. Add a route to the router in `src/main.ts` only if it needs a dedicated screen; the home view auto-renders all lists from `meta.json`.

## Deploy

GitHub Actions (`.github/workflows/deploy.yml`) builds and publishes `dist/` to GitHub Pages on push to `main`. Because of the subpath deploy, keep `base: './'` (relative asset paths) in `vite.config.ts`.
